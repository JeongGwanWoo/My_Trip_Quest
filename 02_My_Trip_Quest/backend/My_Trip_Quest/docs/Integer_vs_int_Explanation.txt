# [Java] int 대신 Integer를 사용한 이유 (feat. MyBatis & DTO)

## TL;DR

-   `int`는 null이 될 수 없다: 데이터베이스의 컬럼 값이 `NULL`일 경우, `int` 타입의 필드에는 담을 수 없어 에러가 발생합니다.
-   `Integer`는 null을 허용한다: `Integer`는 객체(래퍼 클래스)이므로, 데이터베이스의 `NULL` 값을 Java의 `null`로 안전하게 표현할 수 있습니다.
-   결론: 데이터베이스의 데이터를 DTO(Data Transfer Object)로 매핑할 때, `NULL`이 될 가능성이 있는 숫자 컬럼은 `int` 대신 `Integer`를 사용하는 것이 안정적입니다.

---

## 상세 설명

이번 `NoSuchMethodException` 에러는 MyBatis가 데이터베이스 조회 결과를 DTO 객체로 변환하는 과정에서 발생한 타입 불일치 문제였습니다.

### 1. `int` (Primitive Type) 와 `Integer` (Wrapper Type) 의 차이

| 구분         | `int` (원시 타입)                  | `Integer` (래퍼 타입)               |
|--------------|------------------------------------|-------------------------------------|
| **종류**     | 원시 자료형 (Primitive Type)       | 객체 (Object)                     |
| **Null 허용**| **불가 (기본값: 0)**                 | **가능 (기본값: null)**             |
| **성능**     | 더 빠름 (Stack 메모리에 값 저장)       | 상대적으로 느림 (Heap 메모리에 객체 저장) |
| **용도**     | 단순 산술 연산                     | 제네릭, 컬렉션, Null 값 처리가 필요한 경우 |

### 2. 에러 발생 시나리오

1.  **데이터베이스:** `quests` 테이블의 `reward_xp` 컬럼은 정수형이며, 값이 없을 경우 `NULL`이 될 수 있습니다.
2.  **MyBatis:** 데이터베이스에서 `reward_xp` 값을 가져옵니다. JDBC 드라이버는 이 `NULL` 값을 Java의 `Integer` 객체 `null`로 변환하여 DTO 생성자에 전달하려고 시도합니다.
3.  **기존 DTO 코드 (문제 발생):**
    ```java
    // InProgressQuestDto.java
    public class InProgressQuestDto {
        private final int rewardXp; // int 타입

        public InProgressQuestDto(..., int rewardXp, ...) { // int 타입을 받는 생성자
            this.rewardXp = rewardXp;
        }
    }
    ```
4.  **에러:** MyBatis는 `Integer` 타입을 받는 생성자를 찾으려 했지만, DTO에는 `int` 타입을 받는 생성자만 존재했습니다. 이 타입 불일치로 인해 `NoSuchMethodException` (일치하는 메소드/생성자를 찾을 수 없음) 에러가 발생한 것입니다.

### 3. 해결 방법

DTO의 필드와 생성자 파라미터 타입을 `int`에서 `Integer`로 변경하여, 데이터베이스의 `NULL` 값을 `null` 객체로 받을 수 있도록 수정했습니다.

```java
// InProgressQuestDto.java (수정 후)
public class InProgressQuestDto {
    private final Integer rewardXp; // Integer 타입으로 변경

    public InProgressQuestDto(..., Integer rewardXp, ...) { // Integer 타입을 받는 생성자
        this.rewardXp = rewardXp;
    }
}
```

이처럼 데이터베이스와 연동하는 DTO에서는 예기치 않은 `NULL` 값에 대응하기 위해 해당 필드를 원시 타입(`int`, `long`, `double` 등) 대신 래퍼 타입(`Integer`, `Long`, `Double` 등)으로 선언하는 것이 더 안전하고 권장되는 방식입니다.
